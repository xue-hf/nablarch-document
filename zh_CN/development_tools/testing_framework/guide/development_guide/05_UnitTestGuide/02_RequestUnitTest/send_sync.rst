输出库(同步响应消息发送处理)的结构和测试范围
------------------------------------------------------------------------

同步响应消息发送处理的请求单元测试按分配给该处理的请求ID\ [#]_\ 单位进行。

.. [#] 
 此处处理的请求ID是指，为唯一识别消息发送对象系统的功能而定义的ID，
 请注意与Web应用程序或批处理中使用的请求ID含义不同。
 根据此请求ID决定请求报文及响应报文的格式、发送队列名、接收队列名。


※本项中，将Action发送到队列的消息称为「请求报文」、Action从队列接收的消息称为「响应报文」。

请求单元测试实施时的示意图如下所示。

.. image:: ./_image/send_sync_base.png
.. image:: ./_image/hanrei.png


| ①自动测试框架启动Nablarch Application Framework。
| ②Nablarch Application Framework读取作为Action输入的参数，启动Action。
| ③Action执行Nablarch Application Framework的消息同步发送处理。
| ④自动测试框架根据测试数据断言请求报文。

| ⑤自动测试框架根据测试数据生成响应报文，返回给Action。


.. tip::
 自动测试框架不使用「发送队列」「接收队列」，而是在队列前断言请求报文、生成响应报文。
 因此，不需要特别的中间件安装或环境设置。


使用本自动测试框架实施的同步响应消息发送处理的请求单元测试的特点和优点如下。


1. 易于编写的测试数据
 
 报文布局大多字段长度固定，作为测试数据难以记载，但本自动测试框架中，
 通过使用Excel文件，可以按照外部接口设计书的格式定义记载测试数据。

 另外，提供了同步响应消息发送处理专用的测试数据格式，遵循此格式可以轻松创建测试数据。
 这些特点使测试数据易于创建且易于维护。

2. 不需要记述关于消息同步发送处理的测试代码

 测试数据可以记载在Excel中，自动测试框架会根据该测试数据自动进行请求报文的断言及响应报文的返回。

 提供了实现这些典型定型处理的父类，使用它可以进行测试准备、测试目标执行、测试结果确认。
 由此，仅需测试数据，几乎无需编码即可执行测试。

请求报文的期望值以及返回的响应报文的准备
====================================================================================

进行同步响应消息发送处理时，按请求ID分别定义请求报文及响应报文的头部和主体部的格式以及数据。

测试用例与请求报文的期望值及响应报文通过组ID对应。
具体来说，测试用例一览的expectedMessage及responseMessage字段中记载的组ID，
与具有对应标识符的表对应。

另外，如果测试用例一览中没有expectedMessage及responseMessage栏，则不进行验证。
而且如果为空栏，且执行了消息同步发送处理，则测试失败。
如果执行消息同步发送处理，请务必记载expectedMessage及responseMessage。

如果在1个测试用例中，发送同一组ID且同一请求ID的多条报文，请记载该数量的请求报文及响应报文的数据。

关于测试用例的编写方法详情请参考以下。
 * \ :ref:`Web应用程序的测试用例一览<request_test_testcases>`\
 * \ :ref:`批处理的测试用例一览<batch_test_testcases>`\

.. tip::

 Nablarch标准提供的同步响应消息发送功能中，请求报文和响应报文的头部使用共同的格式，
 因此测试数据也同样按请求单位统一头部部的格式定义。
 主体部可以按请求报文和响应报文分别定义不同的格式。


请求报文的期望值以及返回的响应报文的表按以下格式记载。


+---------------------+--------------------------+------------------+--------------+
|标识符               |                                                            |
+---------------------+--------------------------+------------------+--------------+
|指令行               | 指令的设置值             |                                 |
+---------------------+--------------------------+------------------+--------------+
|    ...              |    ...                   |                  |              |
+---------------------+--------------------------+------------------+--------------+
|no                   |字段名称(1)               |字段名称(2)       |...           |
|                     +--------------------------+------------------+--------------+
|                     |数据类型(1)               |数据类型(2)       |...           |
|                     +--------------------------+------------------+--------------+
|                     |字段长度(1)               |字段长度(2)       |...           |
|                     +--------------------------+------------------+--------------+
|                     |数据(1-1)                 |数据(2-1)         |...           |
|                     +--------------------------+------------------+--------------+
|                     |数据(1-2)                 |数据(2-2)         |...           |
|                     +--------------------------+------------------+--------------+
|                     |...                      |...               |...           |
+---------------------+--------------------------+------------------+--------------+


========================== ==================================================================
名称                       说明
========================== ==================================================================
标识符                     指定表示报文种类的ID。本项目与测试用例一览的expectedMessage及responseMessage中记载的组ID关联。
                                                  
                           标识符的格式如下所示。
                                                  
                           * 请求报文的头部期望值 … EXPECTED_REQUEST_HEADER_MESSAGES[组ID]=请求ID
                           * 请求报文的主体期望值 … EXPECTED_REQUEST_BODY_MESSAGES[组ID]=请求ID
                           * 响应报文的头部 … RESPONSE_HEADER_MESSAGES[组ID]=请求ID
                           * 响应报文的主体 … RESPONSE_BODY_MESSAGES[组ID]=请求ID
指令行                     记载指令。在指令名单元格右侧的单元格中记载设置值（可指定多行）。
no                         指令行的下一行必须记载「no」。
字段名称                   记载字段名称。记载字段数量的名称。
数据类型                   记载该字段的数据类型。记载字段数量的类型。

                           数据类型用「半角英文字母」这样的日文名称描述。

                           格式定义文件上的数据类型和日文名称数据类型的映射请参考 BasicDataTypeMapping 的成员变量DEFAULT_TABLE。
字段长度                   记载该字段的字段长度。记载字段数量的长度。
数据                       记载存储在该字段中的数据。如果存在多条记录，则在下一行继续记载数据。
                           如果在1个测试用例中同一请求ID多次同步发送，则在下一行继续记载数据。
========================== ==================================================================


.. tip::
 字段名称、数据类型、字段长度的描述，可以从外部接口设计书复制粘贴来高效创建。
 （粘贴时，请勾选「转置行列」选项）

.. important::

  如果请求报文中存在多条记录，可能会想要如下将多个业务数据记载在1个头部中。

    * 头部
    * 业务数据(第1条记录)
    * 业务数据(第2条记录)
    * 业务数据(第3条记录)

    * 头部
    * 业务数据(第2条记录)
    * 头部
    * 业务数据(第3条记录)

故障系测试
==============

通过在响应报文表中设置以「errorMode:」开头的特定值，可以进行故障系测试。

以下显示设置值与故障系测试的对应关系。

 +------------------------------+-------------------------------------------------------------+--------------------------------------------------+
 | 第一个字段中设置的值           | 故障内容                                                    | 自动测试框架的动作                               |
 +==============================+=============================================================+==================================================+
 |  ``errorMode:timeout``       | 测试消息发送中发生超时错误的情况                            | 抛出 **MessageSendSyncTimeoutException**         |
 |                              |                                                             | (**MessagingException** 的子类)。                |
 +------------------------------+-------------------------------------------------------------+--------------------------------------------------+
 |  ``errorMode:msgException``  | 测试消息收发错误发生的情况                                  | 抛出 **MessagingException** 。                   |
 +------------------------------+-------------------------------------------------------------+--------------------------------------------------+
 
此值记载在响应报文表的头部和正文两者中，除「no」外的第一个字段中。

.. [#]
 如果业务Action中没有显式控制 **MessagingException** ，
 则不需要在各个请求单元测试中进行故障系测试。

--------------
测试结果验证
--------------

如果定义了请求报文的期望值，自动测试框架端会进行以下验证。

* 请求报文内容的验证
* 请求报文发送件数的验证
