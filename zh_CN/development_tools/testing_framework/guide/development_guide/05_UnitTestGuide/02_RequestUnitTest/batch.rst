======================================
请求单元测试的实施方法(批处理)
======================================

--------------------
测试类的编写方法
--------------------

测试类需要满足以下条件进行创建。

* 测试类的包名应与被测Action类相同。
* 以<Action类名>RequestTest作为测试类的类名进行创建。
* 继承\ ``nablarch.test.core.batch.BatchRequestTestSupport``\ 。

例如，被测Action类为\ ``nablarch.sample.ss21AA.RM21AA001Action``\ 时，\
测试类如下所示。

.. code-block:: java

  package nablarch.sample.ss21AA;
  
  // ～中略～

  public class RM21AA001ActionRequestTest extends BatchRequestTestSupport {



------------------
测试方法分割
------------------

原则上1个测试用例对应1个测试方法。
按照以下步骤确定要创建的测试方法。

* 原则上，为1个测试用例创建1个测试方法。
* 作为例外，如果多个用例一起描述效率更高，则研究将多个测试用例放在1个测试方法中。

批处理同时处理多条记录，因此测试数据相对较多。\
如果在1个测试方法中描述多个测试用例，就需要在1个工作表中记载大量测试数据，
导致可读性、可维护性下降。因此原则上采用1测试用例1测试方法。

但是，将多个测试用例一起记载有时效率更高。\
这种情况下研究将多个用例一起描述。

* 测试用例间关联性强，分割工作表会降低可读性的情况。（例：输入文件格式检查的测试用例）


* 测试数据量小，在1个工作表中描述也不会影响可读性、可维护性。


--------------------
测试数据的编写方法
--------------------

记载测试数据的Excel文件与类单元测试一样，
保存在与测试源代码相同的目录中，文件名相同（仅扩展名不同）。

关于测试数据的详细描述方法，请参考「\ :ref:`how_to_write_excel`\ 」。


测试类中通用的数据库初始值
======================================

与Web应用程序的情况相同。请参考「\ :ref:`request_test_setup_db`\ 」。

命令行参数
------------------

说明在测试数据中指定\ :ref:`命令行参数 <main-run_application>`\ 的方法。


要指定批处理启动时的参数，
以\ ``args[n]``\ （\ **下标n为0以上的整数**\ ）的格式添加列。


 == =========== === ======= ======= =======
 no case        ... args[0] args[1] args[2]
 == =========== === ======= ======= =======
 1  xxx的情况   ... 第1参数 第2参数 第3参数
 == =========== === ======= ======= =======

 .. important::
  下标n必须是连续的整数。

如果在测试用例一览中添加上述以外的列，则该列会被视为
命令行选项。

例如，如果测试用例一览中有如下列，


 == =========== === ======== =======
 no case        ...  paramA  paramB
 == =========== === ======== =======
 1  xxx的情况   ...  valueA  valueB
 == =========== === ======== =======

\

.. code-block:: bash

 -paramA=valueA -paramB=valueB

表示指定了这样的命令行选项。

固定长度文件的准备
--------------------

如果在测试数据中记载了固定长度文件的信息，自动测试框架会在测试执行前创建文件。
按以下格式描述。


SETUP_FIXED[组ID]=文件路径
               
指令行

+--------------+------------------+------------------+--------------+
|记录类型      |字段名称(1)       |字段名称(2)       |...  [#]_\    |
|              +------------------+------------------+--------------+
|              |数据类型(1)       |数据类型(2)       |...           |
|              +------------------+------------------+--------------+
|              |字段长度(1)       |字段长度(2)       |...           |
|              +------------------+------------------+--------------+
|              |数据(1-1)         |数据(2-1)         |...           |
|              +------------------+------------------+--------------+
|              |数据(1-2)         |数据(2-2)         |...           |
|              +------------------+------------------+--------------+
|              |... \ [#]_\       |...               |...           |
+--------------+------------------+------------------+--------------+

\ 

.. [#] 
 此处右侧同样继续字段数量的列。

.. [#]
 此处下方同样继续数据数量的行。

\


========================== ========================================================================================================================================================================================================================================================================================================================================================================================
名称                       说明
========================== ========================================================================================================================================================================================================================================================================================================================================================================================
组ID                       指定组ID。与测试用例一览的\ ``setUpFile``\ 中记载的组ID关联。
文件路径                   记载从当前目录开始的文件路径（包含文件名）。
指令行 \ [#]_\             记载指令。在指令名单元格右侧的单元格中记载设置值（可指定多行）。
记录类型                   记载记录类型。如果是多布局，则连续记载此描述。
字段名称                   记载字段名称。记载字段数量的名称。
数据类型                   记载该字段的数据类型。记载字段数量的类型。

                           数据类型用「半角英文字母」这样的日文名称描述。

                           格式定义文件上的数据类型和日文名称数据类型的映射请参考 `BasicDataTypeMapping <https://github.com/nablarch/nablarch-testing/blob/main/src/main/java/nablarch/test/core/file/BasicDataTypeMapping.java>`_ 的成员变量DEFAULT_TABLE。
字段长度                   记载该字段的字段长度。记载字段数量的长度。
数据                       记载存储在该字段中的数据。如果存在多条记录，则在下一行继续记载数据。
========================== ========================================================================================================================================================================================================================================================================================================================================================================================

.. [#]
 描述指令时，格式定义文件的以下内容不需要描述。

 ============== =============================================================
 项目           理由
 ============== =============================================================
 file-type      数据类型的SETUP_FIXED指定表示为固定长度。
 record-length  因为会按字段长度中记载的大小进行填充。
 ============== =============================================================


.. important::
 在1个记录类型中，字段名称中\ **不允许重复的名称**\ 。例如，不允许存在2个以上名为「姓名」的字段。
 （通常，这种情况下会赋予「正式会员姓名」和「家属会员姓名」这样唯一的字段名称）
 
 .. textlint-disable ja-technical-writing/no-doubled-conjunction 
 
 在不同的记录类型间存在相同名称则没有问题。
 （例如，头记录和尾记录中分别存在名为「件数」的字段名称是可以的）
 
 .. textlint-enable ja-technical-writing/no-doubled-conjunction

.. tip::
 字段名称、数据类型、字段长度的描述，可以从外部接口设计书复制粘贴来高效创建。\
 （粘贴时，请勾选「\ **转置行列**\ 」选项）


.. tip::
 使用「无符号数值」和「有符号数值」数据类型时，请直接记载从固定长度文件输入的值（向固定长度文件输出的值）。
 即，如果固定长度文件中存在填充字符或符号，需要记载到这些字符。\
  
 以下显示数据类型为有符号数值时要表示的值及其表现方法的示例。（格式定义：字段长度10位、填充字符'0'、需要小数点、符号位置固定、正号不需要）
 
  =============== ===================== 
  要表示的数值    测试数据上的记载 
  =============== ===================== 
  12345           0000012345 
  -12.34          -000012.34 
  =============== =====================

测试方法的编写方法
----------------------

关于父类
====================

继承\ ``BatchRequestTestSupport``\ 类。
该类根据准备的测试数据按以下步骤执行请求单元测试。


创建测试方法
==================

创建与准备的测试表对应的方法。


.. code-block:: java
    
    @Test
    public void testRegisterUser() {
    }


调用父类的方法
==============================

在测试方法中，调用父类的以下任一方法。

* void execute()
* void execute(String sheetName)

通常情况下，使用execute()。\
带参数的execute方法可以指定测试数据的表名，
但通常测试表名和测试方法名相同。\
使用无参的execute方法，与在测试数据的表名中
指定测试方法名的动作相同。

.. code-block:: java
    
    @Test
    public void testResigster() {
        execute();   // 【说明】与 execute("testRegisterUser") 等价
    }

数据库的结果验证
======================

通过在测试用例一览的expectedTable栏中记载组ID，
可以用该组ID的测试数据确认实际的文件输出结果。



文件的结果验证
==================

通过在测试用例一览的expectedFile栏中记载组ID，
可以用该组ID的测试数据确认实际的文件输出结果。

文件期望值的描述方法与准备数据基本相同。
只有ID的描述方法不同。
以下显示各文件类型的描述方法。

===================== ==============================================  =========================================================
文件类型               无组ID指定                                       有组ID指定
===================== ==============================================  =========================================================
固定长度文件          ``EXPECTED_FIXED=比较对象文件的路径``            ``EXPECTED_FIXED[组ID]=比较对象文件的路径``
可变长度文件          ``EXPECTED_VARIABLE=比较对象文件的路径``         ``EXPECTED_VARIABLE[组ID]=比较对象文件的路径``
===================== ==============================================  =========================================================


日志的结果验证
==============

通过在测试用例一览的expectedLog栏中记载组ID，
可以用该组ID的测试数据确认实际的日志输出结果。


记载以下内容。

+------------------------+----------------------------+
|列名                    |内容                        |
+========================+============================+
|logLevel                |期望日志的日志级别          |
+------------------------+----------------------------+
|message\ **N**\ [#]_\   |期望日志包含的文本          |
+------------------------+----------------------------+

\

.. [#]
 \ **N**\ 指定1以上的整数可以指定多个值（必须是连续的值）
 (例) messsage1, message2...

.. tip::
 这些条件全部为\ **AND**\ 条件。
 以下情况不会被视为输出了期望的日志。
 
 * 期望的文本已输出到日志，但\ **日志级别不符合期望**\ 的情况
 * 日志级别匹配，但有\ **1个**\ 期望的文本未输出到日志的情况
 


具体示例如下。

以下示例中，期望输出2种日志。

``LIST_MAP=expectedLogMessages``

======== ============= ====================== ==============
logLevel   message1     message2               message3
======== ============= ====================== ==============
