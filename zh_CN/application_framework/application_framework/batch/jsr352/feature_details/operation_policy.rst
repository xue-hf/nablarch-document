运维方针
==================================================
.. contents:: 目录
  :depth: 3
  :local:

对于符合 Jakarta Batch 的 Batch 应用，推荐采用以下方针进行故障监控、日志输出。

* :ref:`jsr352-failure_monitoring` 根据 Batch 的结束状态进行。
* 为应对预期可发生的故障（如导入文件不存在等）进行恢复，输出运维人员日志。
* 为调查预期不可发生的故障（如应用缺陷等），输出所有日志。
  关于异常发生时的日志输出，请参考 :ref:`jsr352-batch_error_flow` 。
* 为在 Batch 处理延迟时预测结束时刻，输出进度日志。

遵循这些方针可以获得以下好处。也就是说，发生故障或应对客户咨询时，运维人员能够独立处理的情况会增加，从而可以减轻开发人员的运维负担。

* 发生故障时，如果在运维人员日志中输出了恢复步骤，运维人员可以进行恢复。
* 如果输出了进度日志，开发人员就不需要使用其他手段确认进度状况，
  运维人员可以参考进度日志向客户答复预计结束时间。

.. important::

  Batch 的设计人员应梳理预期可发生的故障及其处理方法，并设计 Batch 以输出到 :doc:`运维人员日志<operator_notice_log>` 。

故障监控
-----------------------------
基于 Batch 的结束状态进行故障监控。
需要详细信息时参考日志。

正常结束
  表示 Batch 处理已正常结束。

异常结束
  表示 Batch 因某种原因异常结束，后续作业无法执行。
  运维人员需要参考日志并进行故障处理。

警告结束
  表示 Batch 执行过程中发生了某种问题，但后续作业可以执行。
  运维人员需要参考日志，确认发生的问题内容。
  
Batch 应用的结束状态（从 Java 进程返回的返回码）详情，请参考 
:java:extdoc:`JobExecutor <nablarch.fw.batch.ee.JobExecutor>` 及 :java:extdoc:`Main <nablarch.fw.batch.ee.Main>` 。

.. tip::

  如果要将结束代码分类得比上述更细，请创建启动类(Main)来对应。

日志的输出方针
-------------------------------

运维人员日志
  输出记载了发生的故障及其处理方法的消息。
  运维人员根据该日志输出的信息进行故障处理。
  详细信息（堆栈跟踪）对运维人员不需要，因此不输出。
  详情请参考 :doc:`operator_notice_log` 。

进度日志
  输出 Batch 处理的进度状况。
  当 Batch 处理延迟时，根据此日志预测当前处理的结束时间，判断是继续还是停止。
  详情请参考 :doc:`progress_log` 。

所有日志
  输出除 ``进度日志`` 外的所有日志。
  对应 ``运维人员日志`` 的详细信息（堆栈跟踪）也输出到此日志中。
