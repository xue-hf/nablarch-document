## 翻译流程

### 1. 准备工作

- 确定要翻译的文件
- 查阅术语表 `TERMINOLOGY.md`
- 阅读原文，理解内容

### 2. 翻译过程

```
ja/xxx/yyy.rst  →  zh_CN/xxx/yyy.rst
```

**AI 执行步骤：**

1. 读取日文原文
2. 查询术语表获取标准翻译
3. 逐段翻译，保持 RST 格式
4. 检查无日文假名残留
5. 保存到目标位置
6. 发现新术语时更新术语表

### 3. 质量检查

**AI 自动检查：**
- [ ] 文件无日文假名（ひらがな/カタカナ）
- [ ] RST 格式正确
- [ ] 术语翻译一致
- [ ] 代码块未改动

### 4. 更新进度

**AI 自动执行：**
- 扫描所有文件
- 统计已翻译/未翻译数量
- 生成并保存 `TRANSLATION_STATUS.md`

## 格式规范

### RST 结构保留

以下 RST 结构必须保留，只翻译内容：

```rst
.. _label_name:              # 标签，不翻译

标题                          # 翻译
================================

.. contents:: 目录            # 翻译"目录"
   :depth: 3                  # 参数不翻译
   :local:

.. tip::                      # 指令不翻译
   提示内容                   # 翻译

.. warning::                  # 指令不翻译
   警告内容                   # 翻译

.. important::                # 指令不翻译
   重要内容                   # 翻译

.. note::                     # 指令不翻译
   注释内容                   # 翻译

* 列表项                     # 翻译
* 列表项                     # 翻译

1. 编号列表                  # 翻译
2. 编号列表                  # 翻译
```

### 链接和引用

```rst
:ref:`label`                 # 引用标签不翻译
:doc:`path/to/file`          # 文档路径不翻译
:java:extdoc:`ClassName`     # Java 类名不翻译
```

## 术语管理

### 术语表维护

**AI 职责：**
- 翻译时优先查询 `TERMINOLOGY.md`
- 发现新术语时添加到术语表
- 定期整理术语表，去重分类

### 术语表格式

**Markdown 格式**（`TERMINOLOGY.md`）：

```markdown
| 日文 | 中文 | 英文 | 备注 |
|------|------|------|------|
| ハンドラ | handler | Handler | 标题用 handler |
```

**JSON 格式**（`terms.json`）：

```json
{
  "ハンドラ": {
    "zh": "handler",
    "en": "Handler",
    "note": "标题用 handler"
  }
}
```

### 术语提取方法

**AI 从已翻译文件中提取：**

1. **标题对照**
   - 对比日文和中文标题
   - 提取：コンセプト → 思想

2. **括号注释**
   - 匹配：ハンドラ(handler)
   - 提取：ハンドラ → handler

3. **正文术语**
   - 识别重复出现的日文词汇
   - 对照中文翻译提取

## 进度更新

### AI 更新进度流程

1. **扫描文件**
   - 遍历 `ja/` 目录获取所有 `.rst` 文件
   - 检查对应 `zh_CN/` 目录下文件是否存在

2. **判断状态**
   - **已翻译**：文件存在且无日文假名
   - **未翻译**：文件与原文相同或包含日文假名
   - **缺失**：文件不存在

3. **生成报告**
   - 统计总数、已翻译数、未翻译数
   - 计算百分比
   - 按模块分类列出文件

4. **保存文档**
   - 更新 `TRANSLATION_STATUS.md`
   - 包含统计表格、文件列表、优先级建议

## 代码处理

### 代码块

代码块内容**不翻译**，只翻译注释：

```rst
.. code-block:: java

   // 这是注释，需要翻译
   public class Example {
       private String name;  // 这是注释，需要翻译
   }
```

### XML 配置

XML 注释翻译，标签和属性名不翻译：

```xml
<!-- 这是注释，需要翻译 -->
<component name="example" class="Example">
    <property name="value" />  <!-- 这是注释，需要翻译 -->
</component>
```

### 类名和方法名

Java 类名、方法名、变量名**保留原文**：

```
✓ nablarch.fw.web.handler.HttpAccessLogHandler
✓ DataReader
✓ ThreadContext
```

## 常见问题

### Q1: 标题如何翻译？

标题通常保留英文关键词：

```
アーキテクチャ → 架构
ハンドラ → handler
バッチ → Batch
```

### Q2: 长句如何翻译？

拆分长句，保持逻辑清晰：

```
日文：
本ハンドラは、リクエスト処理開始時と完了時にアクセスログを出力するハンドラである。

中文：
本 handler 在请求处理开始和完成时输出访问日志。
```

### Q3: 如何处理英文缩写？

首次出现时给出全称和中文：

```
JSP (Jakarta Server Pages) 页面
```

后续可直接使用缩写。

### Q4: 如何判断翻译完成？

**AI 检查：**
- 文件内容不包含日文假名（ひらがな/カタカナ）
- 使用了术语表中的标准翻译
- RST 格式正确

### Q5: 如何更新术语表？

**AI 自动处理：**
1. 发现新术语时添加到 `TERMINOLOGY.md`
2. 同时更新 `terms.json`
3. 分类整理，去重排序

**用户指令：**
```
请将 "スレッドコンテキスト" 添加到术语表
翻译为：线程上下文 (Thread Context)
分类：核心概念
```

### Q6: 如何更新翻译进度？

**AI 自动处理：**
```
请更新翻译进度文档
```

AI 会：
1. 扫描所有文件
2. 统计翻译状态
3. 生成并保存 `TRANSLATION_STATUS.md`
